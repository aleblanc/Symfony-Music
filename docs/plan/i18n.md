# Plan i18n — site multilingue EN / FR

> Statut (2026-10-28) : **phases 0, 1 et 2 implémentées** — 934 clés dans `translations/messages+intl-icu.{en,fr}.yaml`, sélecteur EN/FR dans la sidebar. Reste : relecture FR (tutoiement retenu) et recette visuelle page par page.
> Inventaire produit le 2026-10-28 : **~1 080 occurrences / ~1 000 clés uniques** (annexes A à E).

## 1. Objectif

- Tout texte visible de l'UI web passe par le traducteur Symfony, fichiers **YAML**.
- Deux langues : `en` (défaut + fallback) et `fr`, sélecteur de langue dans la sidebar.
- **Phase 1** : extraire tous les textes anglais dans `translations/messages+intl-icu.en.yaml` (site visuellement identique).
- **Phase 2** : créer `translations/messages+intl-icu.fr.yaml` (la colonne FR des annexes sert de 1er jet).

Hors périmètre :
- commandes console `app:*` (restent en anglais, y compris `app:cron:artist-posts`) ;
- API Subsonic (`src/Controller/Api`, `src/Subsonic` — protocole) ;
- **tout texte stocké en BDD** : métadonnées musicales (BDD/ID3/MusicBrainz/YouTube/Instagram), sentinelles « Unknown Artist/Album/Genre », noms « Mix - X » / « Copy of X », « Deleted User », messages d'échec persistés (suggestions, file d'import), libellés de liens d'artiste (« Official site ») → affichés tels quels ;
- **les URL** : pas de routes traduites ni de préfixe de langue, les URL externes (YouTube, Instagram…) ne bougent pas.

## 2. Choix techniques

### 2.1 Fichiers & format

| Choix | Décision | Pourquoi |
|---|---|---|
| Domaine | `messages+intl-icu` | ICU MessageFormat : vrais pluriels (`{count, plural, one {# titre} other {# titres}}`), `select`, nombres. Le suffixe `+intl-icu` active `MessageFormatter` (ext-intl présente). |
| Fichiers | `translations/messages+intl-icu.en.yaml`, `translations/messages+intl-icu.fr.yaml` | YAML demandé. Arborescent (`nav: { home: Home }`) → clé `nav.home`. |
| Clés | **sémantiques** (`playlist.show.empty`), pas le texte anglais | Corriger un texte EN ne casse pas la traduction FR ; clés stables pour le JS. |
| Partagés | `common.*` (Play, Save, Cancel, compteurs `common.count.*`…) | Évite 30 traductions de « Delete ». |
| Auth Symfony | domaine `security` existant | Symfony fournit déjà `security.fr.xlf` → rien à faire. |
| Placeholders | `{name}` (ICU), jamais de concaténation | L'ordre des mots change en FR. |

`config/packages/translation.yaml` cible :

```yaml
framework:
    default_locale: en
    enabled_locales: ['en', 'fr']
    translator:
        default_path: '%kernel.project_dir%/translations'
        fallbacks: ['en']
```

### 2.2 Choix de la langue (sans préfixe d'URL)

Pas de `/{_locale}/` dans les routes : app perso auto-hébergée, `nav.js` (navigation partielle), PWA/service worker, liens d'embed et d'invitation déjà partagés — un préfixe casserait tout ça pour aucun gain SEO.

`src/EventSubscriber/LocaleSubscriber.php` sur `kernel.request` (priorité **20**, avant le `LocaleListener` du routeur à 16) — ordre de résolution :

1. préférence utilisateur connecté (`User::$settings` JSON → clé `locale`, colonne déjà existante, **pas de migration**) ;
2. session `_locale` ;
3. cookie `locale` (survit à la déconnexion / visiteurs anonymes) ;
4. `Accept-Language` → `$request->getPreferredLanguage(['en', 'fr'])` ;
5. `en`.

Puis `$request->setLocale($locale)`.

### 2.3 Sélecteur de langue

- Route `POST /locale/{locale}` → `app_locale_switch` (`requirements: ['locale' => 'en|fr']`), dans un petit `LocaleController`.
- Jeton CSRF `locale_switch`, écrit session + cookie 1 an (+ `settings.locale` si connecté), puis redirection vers le `Referer` **même origine** sinon `app_home`.
- UI : dans `.sidebar-footer` de `base.html.twig`, deux boutons `EN | FR` (langue courante en `aria-current`), formulaire avec **`data-no-nav`** : il faut un rechargement complet, car `nav.js` ne remplace que `<main>` et la sidebar/le player/le dictionnaire JS resteraient dans l'ancienne langue.
- Option : un sélecteur aussi dans `profile/edit.html.twig` (même route).
- La page autonome `rhythm/hub.html.twig` (n'étend pas `base`) suit simplement la locale de la requête ; pas de sélecteur nécessaire.

### 2.4 Twig

- `{{ 'nav.home'|trans }}`, `{{ 'common.count.tracks'|trans({count: songs|length}) }}`.
- Attributs : `title="{{ 'x.y'|trans }}"` (échappement auto). `confirm()` inline dans `onsubmit` : `{{ 'x.confirm'|trans|e('js') }}`.
- Messages contenant du HTML (`<code>`, `<strong>`) : clé suffixée `_html` + `|trans|raw` — uniquement pour du texte maîtrisé, jamais avec une variable utilisateur non échappée.
- `<html lang="{{ app.request.locale }}">` dans `base.html.twig`, `embed/show.html.twig`, `rhythm/hub.html.twig`.
- Dates / nombres : `composer require twig/intl-extra` → `|format_date('medium')`, `|format_datetime`, `|format_number` à la place de `|date('d/m/Y')`, `|date('l j F')` (jour/mois en anglais sur la home) et `number_format(0, ',', ' ')`.

### 2.5 PHP (flashs, labels serveur)

- Flashs : `$this->addFlash('success', new TranslatableMessage('flash.playlist.copied', ['name' => …]))` et dans `base.html.twig` `{{ message|trans }}` (fonctionne aussi pour une chaîne brute → migration progressive possible).
  Note : vérifier que la session sérialise bien `TranslatableMessage` (c'est un objet simple, OK) ; à défaut `TranslatorInterface::trans()` dans le contrôleur.
- Exceptions métier affichées en flash (`$e->getMessage()` dans Duplicates, Ban, SongVersion, Scanner, Import…) : créer `App\Exception\UserFacingException implements TranslatableInterface` (clé + paramètres). Les erreurs bas niveau (ffmpeg, fs) restent en anglais, préfixées par un message traduit générique.
- Labels générés (titres des étagères Discover, `AudioQuality::label()`, buckets de `QualityStats`, « Official site ») : renvoyer une **clé** (ou `TranslatableMessage`) et traduire dans Twig.
- **Valeurs stockées en BDD** : hors périmètre, on n'y touche pas (ni en base, ni à l'affichage). Les lignes concernées des annexes sont marquées **HORS SCOPE (BDD)**.

### 2.6 JavaScript (`player.js`, `rhythm.js`, scripts inline)

- Toutes les clés JS sont préfixées `js.*`.
- Une fonction Twig `js_translations('js.')` (extension `src/Twig/I18nExtension.php`) lit `TranslatorBagInterface::getCatalogue(locale)` (domaines `messages+intl-icu` + fallback) et renvoie un dict `{clé: message ICU brut}`.
- Injecté dans le JSON existant : `#player-config` (base.html.twig) et `#rhythm-config` (rhythm/hub), avec `locale`.
- Petit helper `public/i18n.js` (~40 lignes, sans dépendance) : `t(key, params)` gérant `{var}` et `{n, plural, one {...} other {...}}` via `Intl.PluralRules(locale)` ; `#` remplacé par le nombre formaté (`Intl.NumberFormat`).
- Remplacer `toLocaleString()` / `toLocaleDateString()` sans argument par `(…, I18N.locale)`.
- Messages JSON renvoyés par le serveur et affichés tels quels par le JS (`data.message`, réglages audio, ban) : traduits côté PHP (la requête porte déjà la locale via session/cookie).

### 2.7 PWA / cache

- `/manifest.json` (`PwaController`) : `name`/`description` traduits selon la locale de la requête, `lang` ajouté.
- Le service worker met le HTML en cache network-first → en ligne, la nouvelle langue s'affiche immédiatement ; hors ligne, la page en cache peut être dans l'ancienne langue (acceptable). Bump de `CACHE_NAME` lors du déploiement de l'i18n.

### 2.8 Outillage / contrôle qualité

```bash
php bin/console lint:yaml translations
php bin/console lint:twig templates
php bin/console debug:translation en --only-missing   # Phase 1 : doit être vide
php bin/console debug:translation fr --only-missing   # Phase 2 : doit être vide
php bin/console debug:translation fr --only-unused
```

Contrôle « texte anglais oublié » : `grep -nE '>[[:space:]]*[A-Z][a-z]+' templates -r | grep -v trans` (heuristique) + revue visuelle de chaque page en FR.
Optionnel : un test PHPUnit qui vérifie que les deux YAML ont exactement le même ensemble de clés.

## 3. Phases

### Phase 0 — Infrastructure (≈ ½ journée)

1. `translation.yaml` : `enabled_locales`, `fallbacks`.
2. `LocaleSubscriber` + `LocaleController` (switch) + sélecteur EN/FR dans la sidebar (`data-no-nav`).
3. `<html lang>` dynamique (3 templates).
4. `composer require twig/intl-extra`.
5. `I18nExtension::js_translations()` + `public/i18n.js` + injection dans `#player-config` / `#rhythm-config`.
6. `base.html.twig` : `{{ message|trans }}` pour les flashs.
7. Créer `translations/messages+intl-icu.en.yaml` (vide) et `…fr.yaml` (vide) → le sélecteur marche, tout reste en anglais via fallback.

### Phase 2 — Traduction FR

1. Générer `translations/messages+intl-icu.fr.yaml` à partir de la colonne **FR** des annexes (même arborescence que l'EN).
2. **Décider tu / vous** : le 1er jet utilise le tutoiement quand une adresse directe est nécessaire (~40 entrées, « Tu as rejoint la playlist ! »), sinon infinitif/impersonnel. Harmoniser selon le choix.
3. Relecture terminologique (glossaire ci-dessous), typographie française : espace insécable avant `: ; ! ?`, guillemets « », points de suspension `…`.
4. `debug:translation fr --only-missing` vide ; revue page par page en FR (desktop + mobile, longueur des libellés dans la sidebar et les boutons).
5. Vérifier formats `format_date` / nombres en FR, et les pluriels (en FR `one` couvre 0 et 1 : « 0 titre »).

## 4. Risques

| Risque | Parade |
|---|---|
| Logique métier qui compare des textes anglais (étagères, buckets qualité) | Introduire des identifiants techniques avant traduction (cf. Phase 1). |
| Navigation partielle `nav.js` : sidebar/player non rafraîchis après changement de langue | Formulaire de switch en `data-no-nav` → rechargement complet. |
| XSS via `|raw` sur des messages traduits | `|raw` seulement pour les clés `_html` sans variable, sinon `|trans` échappé. |
| Clé manquante en FR | Fallback `en` + `debug:translation --only-missing` + test de parité des clés. |
| Textes longs en FR qui cassent la mise en page | Revue mobile en Phase 2. |

### Remarks
- **Concatenated English plurals**: the `{{ n }} thing{{ n == 1 ? '' : 's' }}` pattern appears in offline (8), listen_later (8), favorite/index (8), favorite/albums (9), videos (10) and _rating (11, `n > 1 ? 's'`). Each must become ONE ICU plural message. _disco line 46 always says "tracks" (wrong for 1), and its ICU message fixes that. videos line 19 and _rating line 11 also glue suffixes onto the main text, so split them into complete sentences.
- **Labels generated in PHP**: `AudioQuality::label()` (src/Enum/AudioQuality.php:65) returns English strings shown in the track-row title (_tracks line 32), and probably also in quality/ templates. Make it return a key (`quality.<value>`) or implement `TranslatableInterface`, then `|trans` in Twig. The MusicBrainz `d.type` (_disco 15) and getID3 section names (_raw_metadata 16) are external English values: map them through `disco.type.*` keys or leave them as is. Flash messages (base 79) are rendered raw from `app.flashes`. They are added in about 10 controllers (Ban, ListenLater, Metadata, Profile, Duplicates, Playlist, ArtistProfile, Suggestion, Upload, Song…), so the controllers should store keys or `TranslatableMessage` objects, with `{{ message|trans }}` in base. The `{{ error }}` on the register page (line 10) is likewise an English string from PHP.
- **JS, locale and formatting**:
  - The player and queue panels in base are filled by public/player.js, video-lightbox.js and nav.js. That JS writes its own English text (context menu items, queue counts, toggled title/aria labels, "Clear upcoming" states, lyrics "no lyrics" text, toasts), which these templates cannot cover. Pass a translated JS dictionary through the existing `#player-config` JSON block (base 162–181), e.g. `"i18n": {{ {...}|json_encode|raw }}` with `js.player.*` keys.
  - Set `<html lang="{{ app.request.locale }}">` (base 2).
  - Hard-coded number and date formats: `number_format(0, ',', ' ')` in _disco and `|date('d/m/Y')` in _video_card. Prefer ICU `#` / `format_number` and `format_date` so EN and FR each get the right separators and order.
  - Durations `%d:%02d` are locale-neutral.

### Remarks
- **Plural hacks everywhere**: ~20 occurrences of `track{{ n == 1 ? '' : 's' }}` (also album/artist/genre/year/result, `'es'` for mixes, `' star' ~ (stars > 1 ? 's')`). Replace with `common.count.*` ICU messages; note FR `one` covers 0 so "0 titre" is correct.
- **Concatenations to refactor into one message**: `'Results for “' ~ query ~ '”'` (list), `' for “' ~ query ~ '”'` (mixes), `'Rated: ' ~ label` (ratings, also becomes a default playlist name sent to the server), `', ' ~ app.user.artist` (home Welcome), `song.channels ~ ' channels'`, `· by {creator}` (mix_show). FR quotes should be « » with nbsp.
- **Server-generated labels from PHP**: `shelf.title` (RecommendationService), `quality.label` (Quality enum), `mix.name` / `mix.creator` (possibly generated, e.g. "Daily Mix 1"), `link.label` on artist profile links, `profile.description` (from MusicBrainz, data). These need translation at the service level (TranslatableMessage / return keys).
- **Dates & numbers**: home eyebrow `'now'|date('l j F')` outputs English day/month names → use `format_date` with locale (twig/intl-extra). Other dates use numeric `d/m/Y` (OK, but better via `format_date`). `number_format(0, '.', ' ')` on home and `number_format(…)` for kHz hardcode separators → ICU `{n, number}`. Units: MB→Mo in FR.
- **Inline JS**: only `confirm()` in song/show.html.twig `onsubmit` attr (contains `\n\n`; escape with `|e('js')` inside an HTML attribute — careful with apostrophes in FR "n'est"). Embed inline `<script>` has no user-visible text; `<html lang="en">` hardcoded in embed.
- **HTML inside messages**: folder.html (`<code>`), home guest hint / get started (links + `<code>`), hub login hint, recommendations empty, albums empty. Use placeholders for URLs and `|raw` only after escaping vars, or split the translatable text around the markup.
- **playAll.bar label arg**: folder `label` and ratings `'Rated: ' ~ label` are passed as playlist names to the play-all partial (likely become stored playlist names) — translated at render time, so stored playlists keep the locale used at creation.
- Song audio-settings status text (`#sas-status`) and favourite/offline toggles are driven by external JS (public/*.js), not in these templates — covered by whoever owns the JS files.

### Remarks
- **Server-generated text shown in these templates (needs translating in PHP, not Twig):**
  - `quality/index`: `tier.label` / `t.quality.label` come from `src/Enum/AudioQuality::label()` and `'Unknown bitrate'` in `src/Service/QualityStats.php` (L83, L126); bucket `b.label` and `f.label` built in QualityStats (format labels like "M4A (ALAC)" mostly technical); `listTitle` built in `src/Controller/QualityStatsController.php` L40-49 via `sprintf('Tracks worth replacing (MP3 ≤ %d kb/s, AAC / Vorbis / Opus ≤ %d kb/s)', …)` → should become an ICU message `quality.list.worth_replacing` with `{mp3}`/`{efficient}` placeholders, translated with TranslatorInterface or passed as TranslatableMessage.

### Remarks
- **How JS should receive translations.** Recommended: a `window.I18N` JSON dict rendered server-side, and a tiny `t(key, params)` helper.
  - Add a Twig function/extension (e.g. `js_translations('js.player')`) that pulls all messages with a given prefix from the `TranslatorBagInterface` catalogue (`$translator->getCatalogue($locale)->all('messages+intl-icu')`, filtered by prefix) and emits them as `<script type="application/json" id="i18n">{…}</script>` plus `<html lang="{{ app.request.locale }}">`.
  - base.html.twig renders `js.player.*` (player.js is global). rhythm/hub.html.twig is **standalone** (does not extend base) so it must render its own dict with `js.rhythm.*` + the few `common.*` it needs (`common.unknown_artist`, `common.unknown`, `common.share`, `common.loading`). The existing `#rhythm-config` JSON block (line 725) is a natural place: add `"i18n": {…}` and `"locale": "{{ app.request.locale }}"`.
  - Because messages are ICU (`{count, plural, …}`, `{mode, select, …}`, `{score, number}`), the JS side needs an ICU formatter: either ship `intl-messageformat` (~10 KB) from vendor, or pre-resolve on the client with a minimal formatter that supports `{var}`, `plural` (via `Intl.PluralRules(locale)`) and `select`. Alternative: Symfony UX Translator (`symfony/ux-translator`) dumps the catalogue to JS with ICU support — heavier but standard; it needs AssetMapper/Stimulus, which this app doesn't use (plain /public JS), so the hand-rolled JSON dict is the lighter fit.
  - Avoid data-attributes for JS strings except for per-element dynamic labels; a single dict is easier to keep in sync.
- **JS strings with interpolation/plurals:** player.js — rg.toast_mode (select), rating.stars (plural), queue.count (plural + 2 vars), queue.remove_aria, playing_next, added_to_queue, tracks_added_to_queue (plural), ban.confirm (+fallback), ban.failed. rhythm.js — link_copied, share.score_text (5 vars), leaderboard.total_score/plays (plural), level_badge, level_short, difficulty_level_title, calibration.perfect/late/early, loading.preparing/progress (percent), game.fps, artist_card.score/plays, tracks_count (plural), playlist.search_placeholder, artist.played_times (plural).
- **English plural hacks to refactor:** player.js 366 (`star${n>1?'s':''}`), 610 (`track${…?'':'s'}`); rhythm.js 1652 "Plays", 4537/4940 "Tracks", 4801 "times" (always plural).
- **Number/date formatting:** rhythm.js uses `toLocaleString()` / `toLocaleDateString()` with no argument (browser locale, not app locale) at 1651, 2183, 2275, 2315, 4531, 4802, 4871, 4908 → pass `config.locale` (`toLocaleString(locale)`) or use ICU `{x, number}`. Settings displays "+5ms", "1.0x", "30%" (705, 737, 772) are unit-only; FR would want "5 ms", "30 %" — low priority, could use `Intl.NumberFormat(locale, {style:'percent'})`.
- **Raw enum values shown to users:** pause dialog shows raw difficulty key (`medium`) at rhythm.js 3399; share text uses `selectedDiff.toUpperCase()` (1231); `title="${key.toUpperCase()} level"` (2305, 2666). Map through `js.rhythm.diff_button.*` / `rhythm.difficulty.*`. Judgement strings (PERFECT/GREAT/…) double as internal codes (3895–3921) → translate only when calling `showFeedback`.
- **Difficulty labels are inconsistent** across template (EASY/NORMAL/…), JS button map (Easy/Med/Exprt/Mstr) and three abbreviation maps (EZ/ND or NM/HD/EX/MS/DM at 2254, 2626, 4850). Suggest one `js.rhythm.difficulty.*` + `js.rhythm.diff_abbr.*` set and dedupe the maps. Rank letters (SS/S/A/B/C/F) and "FC" are not translated.

### Remarks
- **Out of scope by design**: `src/Command/**` (console output stays English) and `src/Controller/Api/**` + `src/Subsonic/**` (Subsonic/OpenSubsonic protocol errors such as `SubsonicException::notFound('Album')` are consumed by third-party clients, not the web UI — leave English).
- **Flash rendering**: base.html.twig:79 prints `{{ message }}` raw. Easiest migration: `addFlash($type, new TranslatableMessage('flash.x', [...]))` + `{{ message|trans }}` in base (plain strings still pass through `|trans` untouched). Session serialisation of `TranslatableMessage` is fine. Remember all flash params must be ICU-named (`{name}`), not `%s`.
- **Shelf logic depends on English** — DiscoveryController.php:62 uses `str_starts_with($s['title'], 'Discover')` to position the "Albums to discover" shelf. Once shelf titles are translation keys or translated text this silently breaks: add a stable `key` (e.g. `discover_songs`) to each shelf array in RecommendationService and test that instead; translate `title` in Twig (`shelf.title|trans(shelf.params ?? {})`). Same idea for QualityStats buckets: label is used as array key (l.75) — keep a raw key, translate at display.
- **HORS SCOPE (décision 2026-10-28 : pas de traduction des valeurs stockées en BDD)** — **Persisted English text** (must NOT be translated at write time, or must be translated at display time): `Unknown Artist` / `Unknown Album` / `Unknown Genre` sentinels (MusicScanner:203-205, UploadController:150-157, LibraryPath:29/39, filtered on in MusicRepository/PlayCountRepository SQL) → map in Twig to `common.unknown_artist` / `common.unknown_album` / NEW `common.unknown_genre`; `Mix - {seed}` mix names (MixRepository:113, also matched by the mix search box); `Copy of {name}` playlist names (PlaylistController:106 — translate in the user's locale at creation, it becomes user data); `Deleted User` artist name (ProfileController:288/311); `markFailed()` / `markChoiceFailed()` error strings stored on MetadataSuggestion / ImportItem and re-displayed later (suggestion/index:75, import/queue:60); ArtistProfile link labels "Official site".
- **Exception → flash passthrough**: Duplicates, Ban, SongVersion, MusicScanner, FileImporter, SuggestionApplier and EnrichmentException messages reach users via `$e->getMessage()`. Recommend a small `TranslatableException` (message key + params) for the human-facing ones listed above; keep low-level tool diagnostics in English (MetadataWriter::lastError "AtomicParsley …", getID3 errors, ffmpeg/fpcalc/Chrome messages, MusicBrainzClient HTTP errors) and just wrap them (`flash.artist.musicbrainz_error`, `error.import.tags_not_written`).
- **JSON errors actually displayed today**: only player.js (ban toast: `d.message` / `d.error`; song settings status: `d.error`) and profile edit/show (`alert(data.message)`). The other `error` strings (Favorite/ListenLater/Offline/Rating/Playback/AlbumFavorite/Rhythm) are not shown by the current JS; translate them anyway with shared keys `error.csrf_invalid`, `error.track_not_found`, `error.invalid_json` so they are ready. Note the JS prefixes ("Not banned: ", "Error: ", "Saved.", "Failed to save.") are themselves hardcoded in JS — handled by the JS agent; requests are `fetch()` so the server needs the locale from session/`_locale`, not `Accept-Language` only.
- **Not-found / access-denied exception messages** (`createNotFoundException('Track not found.')`, `'Playlist not found.'`, `'Genre not found or has no visible tracks.'`, `'This track is private.'`, `'Invalid CSRF token.'`, …) are only visible in dev; prod error pages are generic templates (bundles/TwigBundle/Exception, handled by the templates agent). Not inventoried.
- **Login errors** already go through `error.messageKey|trans(error.messageData, 'security')` (security/login.html.twig:10) — Symfony ships the FR `security` catalogue, nothing to add. Registration errors are plain strings in `$error` render param → keys under `validator.*` above; "6" min length hardcoded in two controllers → share `validator.password.too_short` with `{min}`.
- **Number/date formatting in PHP**: QualityStats builds `44.1 kHz` with `number_format(..., '.')` — use ICU `{x, number}` / `{d, date}` for FR decimal commas. `kb/s`, `kHz`, `MB→Mo` units noted in the FR column.
- **Enum labels**: `AudioQuality::label()` returns English; simplest is Twig `('ui.quality.' ~ q.value)|trans` everywhere `quality.label` is used (quality/index, song/show ×2, partials/_tracks title attr) and drop `label()`, or have it return a `TranslatableMessage`.
- **MusicBrainz release types** shown by partials/_disco.html.twig:15 (`d.type` = "EP"; "Album" is hidden) come from the API — "EP" is identical in FR, no key needed. ArtistInfoFetcher already prefers FR Wikipedia (`LANGUAGES = ['fr','en']`) — could follow the user locale later.
- **PWA manifest** (PwaController) is a single static JSON: `short_name`/`description` can only be localised if the manifest route becomes locale-aware.
